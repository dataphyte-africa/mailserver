# 2027 State Focal Point applications

This is a Foundation-owned recruitment form, separate from newsletter subscription forms and the Observer Violations report form. The public URL is `/applications/2027-state-focal-points`. It has four sections: personal information, election-observation experience, coordination/reporting capacity, and Terms of Reference. The deadline is **Thursday, 29 October 2026, 11:59 PM Africa/Lagos** (the source copy had the wrong weekday).

## Data flow

- State, LGA and ward options are fetched through the application's cached election-location service. The existing `DATAPHYTE_ELECTION_API_TOKEN` is read server-side if set; it is never sent to the browser. Only Nigerian states and FCT are offered. Submitted IDs are revalidated against their parent location and names are snapshotted with the application.
- Location controls are progressively enhanced with searchable, fixed-height result lists and keyboard navigation; the native selects remain as a no-JavaScript fallback.
- Applicants must scroll to the end of the ToR and tick acknowledgement. The server requires the acknowledgement and records its version and timestamp; client-side scrolling is a reading affordance, not a security claim.
- The super-admin Application Forms card links to a Statamic global with editable hero and introduction copy, a Bard ToR, and an Africa/Lagos closing date plus an immediate close/reopen switch. Saving changed terms invalidates the prior approval hash. The super admin must approve the current terms from the Application Forms card; each submission stores the exact sanitised HTML, hash and acceptance time.
- Closing the form replaces it with a dedicated closed page and rejects POSTs with HTTP 410. A future deadline plus the accepting-submissions switch reopens it. Generic product-owned application/data-collection forms have the same window controls in their CP editor and use the same closed page. The legacy Osun observer application uses its existing Statamic closing-date setting and now shows the same closed page after that date.
- The public POST requires two distinct files: a CV (PDF/DOC/DOCX) and highest-qualification certificate (PDF/image/DOC/DOCX). The default limit is 10 MB **per file**; the CV two-page instruction is checked during review, not by the server.
- The application receives `pending_review` only after **both** uploads succeed in Google Drive. If the second upload or database write fails, the app attempts to delete any file already uploaded. A failed delete needs manual orphan cleanup from the Drive folders.
- The CV is written to folder `13syUofa223-tCfO_gCWP4gcCe8XZVaf6`; the certificate to `1ti9A02QxtSBFzpregUK2uaXNa9Iw0F9k`. These IDs can be overridden by environment variables. Files inherit the folders' Google sharing policy; do not enable “Anyone with the link.”
- Only a Statamic super admin can access `/cp/focal-point-applications`, change review status, or export CSV. The CSV includes separate stable Google Drive links. Google independently checks the viewer's Google account and folder permissions when a link is opened. CSV values are escaped against spreadsheet formula execution.

## Google Workspace setup

1. Keep both destination folders set to **Restricted** and grant viewer access only to named reviewers. Grant the app's dedicated Workspace uploader account Editor access to both folders. My Drive files uploaded by that account are owned by that account, even when placed in another user's folder; plan account continuity accordingly.
2. In a Google Cloud project controlled by the organisation, enable Drive API and create an **internal** OAuth client. Authorise the dedicated uploader account for Drive access with offline access and obtain a refresh token through Google's OAuth flow. Store the client ID, client secret and refresh token only in the deployment environment. Do not paste them into source control or chat.
3. Set `GOOGLE_DRIVE_CLIENT_ID`, `GOOGLE_DRIVE_CLIENT_SECRET`, `GOOGLE_DRIVE_REFRESH_TOKEN`, `GOOGLE_DRIVE_CV_FOLDER_ID`, and `GOOGLE_DRIVE_CERTIFICATE_FOLDER_ID`. The folder IDs default to the two folders supplied for this application. The existing election API token is separate from Google credentials.
4. Set PHP `upload_max_filesize` to at least the configured per-file limit and `post_max_size` above the combined size of both files plus form fields. Configure the reverse proxy's request-body limit likewise. Run migrations and clear cached config after deployment.
5. Test with a non-sensitive submission: confirm both folders receive the right file, a super admin can export the row, an authorised reviewer can open each CSV link, and an unauthorised Google account cannot.

The public form requires all Google Drive OAuth settings. Outside `APP_ENV=local`, it also requires ToR approval in the CP before accepting submissions. Local-only submissions may use the current draft terms for testing, but never use real applicant data for those tests. The ToR currently covers all Nigerian states and FCT. The supplied election date says 16 January 2026 in a 2027 call; the fee text says both N200,000 and N500,000 while the listed components total N60,000. These clauses were deliberately omitted rather than silently corrected. Edit them in Bard after the wording is confirmed, save, then approve the new version in Application Forms before production launch. The integration has automated HTTP-fake tests but **has not been validated against the real Workspace folders or credentials**. Review status changes do not send outcome emails; the team must contact applicants separately unless a notification workflow is approved and implemented. Before launch, approve document retention/deletion rules and the applicant privacy notice for sensitive personal information.
